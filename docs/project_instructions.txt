공유해주신 리포지토리(dtruongthinh2409/franka_isaaclab)의 핵심 시연 가치(Core Demonstrations) 7가지를 실제로 학습하고 프로젝트에 적용하는 구체적인 방법론과 관련 소스코드 위치를 정리해 드립니다.
이 가이드를 따라가시면 Isaac Lab 기반의 하이엔드 로봇 강화학습 아키텍처를 완벽하게 고도화할 수 있습니다.
1. Custom RL Environment Design (Isaac Lab 환경 설계)
Isaac Lab 프레임워크 내에서 나만의 로봇, 객체, 물리 법칙을 커스텀 정의하는 방법입니다.
구현 방식: Isaac Lab의 매니저 기반(Manager-based) 구조를 따르며, 로봇 에셋(AssetCfg), 환경 레이아웃(SceneCfg), 관측(ObservationCfg), 초기화 조항 등을 파이썬 클래스로 선언합니다.
학습 및 실습 방법:
1. source/franka_isaaclab/franka_isaaclab/assets/robots/franka.py에서 Franka 로봇의 관절 제어 모드(강성, 감쇠 등)를 분석합니다.
2. reach_env_cfg.py나 lift_env_cfg.py를 열어 테이블, 큐브 등의 에셋이 InteractiveSceneCfg에 어떻게 등록되는지 파악합니다.
3. 환경을 새로 만들면 franka_isaaclab/tasks/manager_based/__init__.py 파일에 gymnasium.register()를 사용해 고유의 환경 ID(예: Template-MyTask-v0)로 등록합니다.
2. Reward Engineering (복잡한 조작을 위한 보상 함수 설계)
로봇이 원하는 정밀한 조작을 수행하도록 수학적 보상 함수를 설계(Shaping)하는 기법입니다.
구현 방식: 단순한 Linear 보상 대신, 목표 거리에 가까워질수록 보상이 기하급수적으로 커지는 $\tanh$-kernel 함수를 활용하고, 하드웨어 무리를 방지하는 패널티 항목을 결합합니다.
학습 및 실습 방법:
* 각 태스크 폴더 하위의 mdp/rewards.py 파일을 분석합니다.
* 거리 보상 튜닝: exp(-dist^2 / sigma^2) 형태의 수식에서 임계값 $\sigma$(sigma)를 조절하여 로봇이 물체 주변에서 얼마나 민감하게 반응할지 수정해 봅니다.
* 평활화(Smoothness) 패널티: action_rate_l2 보상 항을 조절하여 로봇 팔의 덜덜거림(Oscillation)을 억제하는 법을 익힙니다.
3. Curriculum Learning (단계별 커리큘럼 학습)
태스크의 난이도를 점진적으로 높여 신경망이 복잡한 행동을 쉽게 수렴하도록 돕는 기법입니다.
구현 방식: 본 리포지토리는 프로젝트 자체가 거대한 커리큘럼 아키텍처입니다. 팔만 뻗는 기초 과제부터 복합 적재 과제까지 단계별로 구성되어 있습니다.
학습 및 실습 방법:
1단계 (Reach): Template-Reach-v0를 약 24,000 스텝 학습시켜 말단 작동기 제어 성능을 확보합니다.
2단계 (Lift): 그리퍼 제어가 추가된 Template-Lift-v0를 36,000 스텝 학습시켜 물체 파지 역량을 결합합니다.
3단계 (Stack): 앞서 배운 파지와 이동 기술을 결합하여 최상위 난이도의 적재 과제를 최종 정복합니다.
4. Multi-Stage Task Decomposition (장기 태스크 분할 기법)
Stack 과제와 같이 한 번에 성공하기 힘든 고난도 과제(Long-Horizon)를 5개의 하위 스테이지로 쪼개어 해결하는 방식입니다.
구현 방식: tasks/manager_based/stack/mdp/rewards.py 내부에 로봇의 현재 상태(Grasp 유무, 위치 정렬 등)를 조건문으로 판단하여 단계별 보상을 활성화합니다.
학습 및 실습 방법:
* franka_stack_events.py에서 그리퍼가 물체를 완벽히 잡았는지 감지하는 커스텀 이벤트 핸들러를 분석합니다.
* 큐브 1을 들어 올리기 전에는 3단계(Move) 및 4단계(Stack) 보상이 활성화되지 않도록 차단하는 '보상 잠금(Gating) 메커니즘'의 코딩 방식을 학습합니다.
5. Integration with Modern RL Libraries (SKRL & Gymnasium 연동)
표준 강화학습 인터페이스인 Gymnasium과 GPU 가속 최적화 라이브러리인 SKRL을 결합하는 방법입니다.
구현 방식: Isaac Lab 환경을 표준 gymnasium.Env로 래핑하고, skrl의 PPO(Proximal Policy Optimization) 알고리즘 파이프라인에 연결합니다.
학습 및 실습 방법:
* 각 태스크의 agents/skrl_ppo_cfg.yaml 파일을 열어 하이퍼파라미터(learning_rate, mini_batches, discount_factor 등) 설정을 확인합니다.
* scripts/skrl/train.py에서 Isaac Lab 환경의 VecEnv(벡터화 환경)가 어떻게 SKRL의 에이전트와 데이터 통신을 주고받는지 메인 루프를 분석합니다.
6. GPU-Accelerated Simulation (VRAM 기반 고속 학습)
NVIDIA PhysX 파이프라인을 CPU가 아닌 GPU 위에서 완전히 구동시켜 학습 속도를 극대화하는 기법입니다.
구현 방식: 수십~수천 개의 시뮬레이션 환경 환경 데이터를 CPU 복사 없이 GPU 텐서(torch.Tensor)로 직결하여 연산 병목을 제거합니다.
학습 및 실습 방법:
* 학습 스크립트 실행 시 --num_envs=32 또는 --num_envs=64 옵션을 주어 병렬 가상 세계를 다수 생성하는 법을 연습합니다.
* 시각화 화면(렌더링 부하)을 차단하여 오직 물리 연산과 신경망 역전파에만 VRAM을 집중시키는 --headless 모드를 적극 활용하여 수만 스텝의 학습을 수 분 내에 끝내는 성능을 체감합니다.
7. Checkpoint Management & Versioning (체크포인트 및 모델 관리)
학습 도중 최고 성능을 낸 모델 가중치를 자동으로 저장하고, 실험 리포트를 트래킹하는 방법입니다.
구현 방식: SKRL 내부 트레이너가 학습 주기마다 보상을 평가하여 best_agent.pt 파일을 타임스탬프 형식의 폴더 구조로 분리 저장합니다.
학습 및 실습 방법:
1. 학습을 돌리면 logs/skrl/<태스크명>/<날짜_시간>_ppo_torch/checkpoints/ 경로에 가중치가 백업됩니다.
2. tensorboard --logdir=logs/skrl/ 명령어를 통해 학습 성과 곡선을 시각적으로 버전 관리합니다.
3. scripts/skrl/play.py --checkpoint=<경로> 스크립트를 사용해 과거에 저장해 둔 특정 버전의 체크포인트를 언제든 시뮬레이터에 로드하여 재생(Inference)할 수 있습니다.

📊 3단계: MDP 관리자 및 환경 통합 클래스 선언
동일한 파일(my_custom_env_cfg.py) 하단에 로봇이 관측할 정보(Observation), 행동 제어 방식(Action), 보상(Reward), 종료 조건(Termination)을 설계하는 MDP 매니저 구성을 추가합니다.

from omni.isaac.lab.managers import ActionManagerCfg, ObservationManagerCfg, RewardManagerCfg, TerminationManagerCfg
import omni.isaac.lab.managers.mdps as mdp

@configclass
class MyCustomObservationsCfg(ObservationManagerCfg):
   """신경망에 전달될 24차원 내외의 관측 공간 정의"""
    @dataclass
   class PolicyCfg(ObservationManagerCfg.PolicyCfg):
       # 로봇 관절 위치 정보수집
       joint_pos = mdp.ObservationTermCfg(func=mdp.joint_pos_rel)
       # 로봇 관절 속도 정보수집
       joint_vel = mdp.ObservationTermCfg(func=mdp.joint_vel_rel)
       # 목표 큐브의 절대 위치 정보수집
       cube_pos = mdp.ObservationTermCfg(func=mdp.object_position, params={"asset_cfg": "cube"})

   policy: PolicyCfg = PolicyCfg()

@configclass
class MyCustomActionsCfg(ActionManagerCfg):
   """행동 공간: 7개 조인트의 위치 제어 명령"""
   arm_action = mdp.ActionTermCfg(
       func=mdp.joint_position_high_level,
       params={"asset_cfg": "robot", "joint_names": ["panda_joint.*"]}
   )

@configclass
class MyCustomRewardsCfg(RewardManagerCfg):
   """보상 엔지니어링 설계"""
   # 1. 목표 거리가 가까울수록 가중치 부여 (기존 mdp 수식 빌려오기)
   cube_distance = mdp.RewardTermCfg(
       func=mdp.object_ee_distance,
       weight=1.0,
       params={"asset_cfg_a": "robot", "asset_cfg_b": "cube"}
   )
   # 2. 과도한 떨림 현상을 조절하기 위한 액션 패널티
   action_rate = mdp.RewardTermCfg(func=mdp.action_rate_l2, weight=-0.01)

@configclass
class MyCustomTerminationsCfg(TerminationManagerCfg):
   """에피소드가 끝나는 리셋 조건 설정"""
   # 에피소드 최대 타임스텝 도달 시 리셋
   time_out = mdp.TerminationTermCfg(func=mdp.time_out, time_out=True)


@configclass
class MyCustomEnvCfg(ManagerBasedRLEnvCfg):
   """종합 커스텀 환경 설정 패키징"""
   scene: MyCustomSceneCfg = MyCustomSceneCfg()
   observations: MyCustomObservationsCfg = MyCustomObservationsCfg()
   actions: MyCustomActionsCfg = MyCustomActionsCfg()
   rewards: MyCustomRewardsCfg = MyCustomRewardsCfg()
   terminations: MyCustomTerminationsCfg = MyCustomTerminationsCfg()

2. Reward Engineering (복잡한 조작을 위한 보상 함수 설계)
NVIDIA Isaac Lab의 매니저 기반(Manager-based) 아키텍처 환경에서 복잡한 로봇 조작 과제를 해결하기 위한 실전 보상 엔지니어링(Reward Engineering) 개발 매뉴얼 및 실행 가이드입니다.
강화학습 에이전트의 영리한 움직임과 하드웨어 안정성을 동시에 확보할 수 있는 보상 수식 설계부터 디버깅 기법까지 구체적으로 명시되어 있습니다.
📊 1. Isaac Lab 보상 시스템 아키텍처 이해

🧮 2. 고난도 조작을 위한 수학적 보상 모델링
단순한 선형 거리 보상($-d$)은 에이전트가 목표물 근처에서 정밀하게 밀착하지 못하고 주위를 빙빙 도는 현상(Orbiting)을 유발합니다. 이를 해결하기 위해 비선형 커널과 평활화 패널티를 매핑해야 합니다.
① 자석 효과를 위한 $\tanh$-kernel (또는 Exponential) 거리 보상
목표물과의 거리를 $d$라고 할 때, 멀리 있을 때는 보상의 변화가 완만하다가 목표 영역에 진입하는 순간 점수가 폭발적으로 증가하도록 유도합니다.


$$R_{\text{dist}} = w \cdot \exp\left(-\frac{d^2}{\sigma^2}\right)$$
실제 파이썬 코드 구현 (mdp/rewards.py):
Python
import torch
from omni.isaac.lab.assets import Articulation, RigidObject

def object_ee_distance(env, asset_cfg_a: str, asset_cfg_b: str, sigma: float = 0.1) -> torch.Tensor:
   # 에셋 매니저에서 로봇 및 물체 인스턴스 참조
   robot: Articulation = env.scene[asset_cfg_a]
   target: RigidObject = env.scene[asset_cfg_b]

   # 말단 작동기(EE) 위치와 타겟 큐브의 위치 추출
   ee_pos = robot.data.ee_w_pos  # 에셋 세팅에 따른 EE 위치 텐서
   target_pos = target.data.root_pos_w

   # 배치 환경 전체의 유클리드 거리 연산
   d = torch.norm(target_pos - ee_pos, dim=-1)

   # Gaussian/Tanh 스타일 커널 반환
   return torch.exp(-torch.square(d) / (sigma ** 2))



튜닝 핵심 가이드: σσ(sigma) 파라미터는 민감도를 결정합니다. σσ가 너무 작으면(0.020.02) 목표물과 완전히 포개어질 때만 보상이 주어져 초기 탐색에 실패합니다. 최초 연습 시에는 0.1∼0.20.1∼0.2 수준으로 너그럽게 시작하는 것이 좋습니다.
② Sim2Real 배포를 위한 평활화 패널티 (Action Smoothness)
시뮬레이션에서만 잘 움직이고 현실 로봇에 올렸을 때 관절이 덜덜 떨리며 모터가 과열되는 현상을 방지하는 필수 안전 장치입니다.
* Action Rate L2 Penalty: 이전 타임스텝 명령어와 현재 명령어가 급격하게 바뀌는 변화량 차이를 감점합니다.
Rsmooth=−λ∑∥at−at−1∥2Rsmooth​=−λ∑∥at​−at−1​∥2
* 주의 사항: 패널티의 가중치(λλ)가 포지티브 보상보다 커지면, 로봇은 감점을 피하기 위해 움직임을 완전히 멈추는 부작용(Frozen Policy)에 빠집니다. 항상 메인 성취 보상 기대값의 **1%∼5%1%∼5% 수준(−0.005∼−0.01−0.005∼−0.01)**으로 미미하게 걸어주어야 합니다.

🧱 3. 다단계(Multi-Stage) 조건부 가이딩 보상 설계 (Stack 태스크 방식)
큐브를 들어 올려 다른 큐브 위에 쌓는 연속 조작 과제는 초기 단계 보상이 잠금 해제되어야 다음 단계 보상이 풀리는 시퀀싱(Gating Mechanism) 기법이 필수적입니다.
def multi_stage_stack_reward(env) -> torch.Tensor:
        dist_to_cube1 = get_distance(env, "robot", "cube1")  
dist_cube1_to_cube2 = get_distance(env, "cube1", "cube2")  
  
# Custom event handler 등을 이용해 그리퍼 파지 성공 여부 검출  
is_grasped = env.event_manager.functions["grasp_detection"](env)  
  
reward = torch.zeros_like(dist_to_cube1)  
  
# [Stage 1] 물체를 잡기 전: Cube 1에 접근하도록 유도  
reward += torch.where(~is_grasped, torch.exp(-dist_to_cube1 / 0.1), torch.zeros_like(reward))  
  
# [Stage 2] 파지 성공 후: 접근 보상을 차단하고, Cube 2로 정렬 이동하는 보상 전격 활성화  
grasp_bonus = 2.0  
stack_align = torch.exp(-dist_cube1_to_cube2 / 0.05)  
  
reward += torch.where(is_grasped, grasp_bonus + stack_align, torch.zeros_like(reward))  
  
return reward

3. Curriculum Learning (단계별 커리큘럼 학습)
NVIDIA Isaac Lab 환경에서 복잡한 로봇 조작 과제를 마스터하기 위한 커리큘럼 학습(Curriculum Learning)의 실제 구현 및 단계별 실행 가이드입니다.
강화학습에서 커리큘럼 학습은 난이도가 너무 높아 에이전트가 우연히도 보상을 얻지 못하는 '희소 보상(Sparse Reward)' 문제를 해결하기 위한 필수 기법입니다. 본 리포지토리는 크게 거시적 커리큘럼(태스크 간 연속 학습)과 미시적 커리큘럼(태스크 내부 다단계 스케일링) 두 가지 아키텍처를 시연합니다. 이를 직접 구동하고 커스텀하는 방법을 상세히 정리해 드립니다.
🗺️ 1. 커리큘럼 학습 아키텍처 개요
본 프로젝트는 복잡도를 계층적으로 분리하여 로봇의 인지 및 제어 능력을 점진적으로 빌드업합니다.

단계 1: Template-Reach-v0 (7축 관절 위치 제어 및 공간 이동 학습)
       👇 (팔 뻗기 능력이 검증되면)
단계 2: Template-Lift-v0  (그리퍼 제어 축 추가 및 객체 물리적 파지 학습)
       👇 (물체 파지 능력이 검증되면)

🛠️ 2. 미시적 커리큘럼(태스크 내부 Stage-gating) 구현 방법
가장 난이도가 높은 Template-Stack-v0 내부에서는 한 에피소드 안에서 로봇의 성취도에 따라 보상 함수의 가중치와 환경의 물리적 난이도를 실시간으로 가변시키는 단계별 게이팅(Stage-gating) 메커니즘이 작동합니다.
소스코드 수준에서의 커리큘럼 작동 메커니즘 (mdp/rewards.py)
에이전트가 이전 단계를 완수했는지 판단하는 임계값(Threshold)을 걸어두고, 이 조건이 만족될 때만 상위 난이도의 보상 활성화 잠금을 해제(Unlock)합니다.
Python
import torch

def curriculum_stack_reward(env) -> torch.Tensor:
   # 1. 현재 에피소드의 물리적 진행 상태 수집
   dist_ee_to_cube1 = get_distance(env, "robot", "cube1")
   dist_cube1_to_cube2 = get_distance(env, "cube1", "cube2")
   is_cube1_lifted = env.scene["cube1"].data.root_pos_w[:, 2] > 0.4
   
   reward = torch.zeros_like(dist_ee_to_cube1)
   
   # [Stage 1-2 게이팅] 아직 cube1 근처에 가지 못했다면 Reach 보상만 전폭 지원
   stage1_mask = dist_ee_to_cube1 > 0.05
   reward += torch.where(stage1_mask, torch.exp(-dist_ee_to_cube1 / 0.1), torch.zeros_like(reward))
   
   # [Stage 3-4 게이팅] cube1을 성공적으로 잡아서 들어 올렸을 때만 Stack 정렬 보상 라인 활성화
   stage3_mask = ~stage1_mask & is_cube1_lifted
   align_reward = torch.exp(-dist_cube1_to_cube2 / 0.05)
   
   reward += torch.where(stage3_mask, 2.0 + align_reward, torch.zeros_like(reward))
   
   return reward

2. 이상적인 커리큘럼 수렴의 차트 형태 확인법

   * 학습 초기 (0 ~ 10k 스텝): Rew/cube_reach 점수는 가파르게 상승하지만, Rew/align_stack 점수는 바닥($0$)에 누워있어야 정상입니다. (아직 1단계를 못 깨서 상위 단계 보상이 잠겨있는 상태)
   * 학습 중기 (10k ~ 20k 스텝): 로봇이 물체를 잡기 시작하면서 Rew/cube_reach가 포화 상태에 이르고, 드디어 잠겨있던 Rew/grasp_bonus와 Rew/align_stack 차트가 깨어나며 위로 고개를 들기 시작합니다.
   * 학습 후기 (20k 스텝 이후): 앞선 스테이지 보상들이 견고하게 높은 값을 유지하면서, 최종 단계인 Rew/stack_stability 보상 곡선이 상승 곡선을 그립니다.
⚠️ 트러블슈팅 팁: 만약 30k 스텝이 지났는데도 Rew/align_stack 보상 차트가 계속 $0$에 머물러 있다면, 로봇이 1~2단계 조건(정확하게 큐브를 쥐고 들어 올리기)을 달성하는 난이도가 너무 높아서 상위 커리큘럼으로 진입을 아예 못 하고 있는 상태입니다. 이 경우 stack_env_cfg.py에서 초기 두 큐브의 거리를 가깝게 좁혀주거나, 1단계 진입 임계값 허용 오차를 조금 더 널널하게 키워주는 물리적 커리큘럼 조절이 필요합니다.
현재 구상 중이시거나 연습 중이신 프로젝트 구조에서 로봇 팔이 첫 번째 물체를 잡으러 내려가는 단계(Stage 1) 자체를 실패하나요, 아니면 잡는 것까지는 잘하는데 그다지 정렬하지 못하고 떨어뜨리는 단계(Stage 3~4)에서 주로 병목이 발생하나요? 문제가 되는 정체 구간을 알려주시면 커리큘럼 임계값 파라미터 제어 팁을 더 구체적으로 가이드해 드리겠습니다.

4. Multi-Stage Task Decomposition (장기 태스크 분할 기법)
NVIDIA Isaac Lab의 매니저 기반(Manager-based) 프레임워크에서 장기 태스크 분할(Multi-Stage Task Decomposition) 기법을 활용하여 고난도 조작 과제(Long-Horizon Manipulation)를 체계적으로 해체하고 구현하는 실전 가이드라인입니다.
강화학습 에이전트가 큐브를 집어서 다른 큐브 위에 쌓는 복합 연쇄 모션을 한 번에 학습하려면 성공 확률이 극도로 낮아 학습이 수렴하지 않습니다. 이를 극복하기 위해 물리적 상태에 따라 보상 체계를 조건부로 전환하는 스테이지 게이팅(Stage-Gating) 메커니즘의 설계 및 실행 단계를 구체적으로 정리해 드립니다.
1. 실전 5단계 분할 설계 매트릭스 (Task Matrix)
먼저 전체 Stacking 공정을 논리적 인과관계에 따라 5개 스테이지로 분할하고, 각 단계가 활성화되는 물리적 트리거 조건과 매칭 보상을 정의하는 매트릭스를 구성해야 합니다.
스테이지
	하위 목표
 (Sub-goal)
	진입 조건 
(Trigger Condition)
	핵심 활성화 보상 
(Active Rewards)
	Stage 1
	Reach: 큐브 1에 접근
	에피소드 시작 직후 (초기 상태)
	말단 작동기(EE)와 큐브 1 사이의 거리 보상
	Stage 2
	Grasp & Lift: 파지 및 고도 확보
	EE가 큐브 1에 밀착 완료 ($d < 3\text{cm}$)
	그리퍼 압착 명령 유도, 큐브 1의 고도 상승 보상, 파지 보너스
	Stage 3
	Move: 큐브 2로 이동
	큐브 1이 지면에서 이탈 완료 ($z > 10\text{cm}$)
	큐브 1과 큐브 2 사이의 수평($X, Y$) 거리 좁히기 보상
	Stage 4
	Align & Stack: 수직 정렬 및 적재
	큐브 1이 큐브 2의 상단 영역에 진입
	두 큐브의 $X, Y$ 중심축 일치 패널티 감점, 부드러운 하강 보상
	Stage 5
	Release & Verify: 해제 및 안정성 검증
	큐브 1이 큐브 2 상단에 안착 완료
	그리퍼 개방 유도, 로봇 팔 후퇴 모션 보상, 적재 유지 시간 보너스
	

2. 소스코드 구현 가이드 (mdp/rewards.py 설계)
Isaac Lab 환경에서 수백 개의 병렬 가상 세계가 GPU 위에서 동시에 돌아가므로, 모든 스테이지 전환 조건은 파이썬의 if-else문이 아닌 PyTorch 텐서 연산(torch.where) 형태로 병렬 처리되어야 합니다.
source/franka_isaaclab/franka_isaaclab/tasks/manager_based/stack/mdp/rewards.py 파일 내에 분할 기법을 구현하는 핵심 패턴 아키텍처입니다.


Python




import torch
from omni.isaac.lab.assets import Articulation, RigidObject
from omni.isaac.lab.envs import ManagerBasedRLEnv

def multi_stage_stacking_reward(
   env: ManagerBasedRLEnv, 
   robot_name: str = "robot", 
   cube1_name: str = "cube1", 
   cube2_name: str = "cube2"
) -> torch.Tensor:
   """5단계 장기 태스크 분할 제어를 위한 통합 커리큘럼 보상 함수"""
   
   # 1. 시뮬레이션 씬에서 각 에셋 데이터 참조 추출
   robot: Articulation = env.scene[robot_name]
   cube1: RigidObject = env.scene[cube1_name]
   cube2: RigidObject = env.scene[cube2_name]
   
   # 2. 물리적 특징량 계산 (위치 벡터 및 유클리드 거리)
   ee_pos = robot.data.ee_w_pos          # 말단 작동기 중심 좌표 (Batch, 3)
   c1_pos = cube1.data.root_pos_w        # 큐브 1 중심 좌표 (Batch, 3)
   c2_pos = cube2.data.root_pos_w        # 큐브 2 중심 좌표 (Batch, 3)
   
   dist_ee_to_c1 = torch.norm(c1_pos - ee_pos, dim=-1)
   dist_c1_to_c2 = torch.norm(c2_pos - c1_pos, dim=-1)
   
   # 3. 스테이지 전환을 위한 Boolean 마스크 정의 (Gating Flags)
   # 예: 커스텀 이벤트 매니저나 접촉 센서 버퍼에서 파지 여부 플래그 획득
   is_c1_grasped = env.event_manager.functions["check_grasp_success"](env)
   is_c1_lifted = (c1_pos[:, 2] - env.scene["table"].data.root_pos_w[:, 2]) > 0.15
   is_aligned = torch.norm(c1_pos[:, :2] - c2_pos[:, :2], dim=-1) < 0.03
   
   # 4. 전체 배치 크기에 맞게 초기 보상 텐서 선언
   total_reward = torch.zeros(env.num_envs, device=env.device)
   
   # ------------------------------------------------------------------
   # [Stage 1] Reach Mode: 아직 물체를 안정적으로 잡지 못했을 때
   # ------------------------------------------------------------------
   r_reach = torch.exp(-torch.square(dist_ee_to_c1) / (0.1 ** 2))
   total_reward = torch.where(~is_c1_grasped, r_reach, total_reward)
   
   # ------------------------------------------------------------------
   # [Stage 2 & 3] Grasp & Move Mode: 파지 성공 후 큐브 2로 이동할 때
   # ------------------------------------------------------------------
   r_lift = 2.0 + (c1_pos[:, 2] * 5.0)  # 들어올리기 가속화 보상
   r_move = torch.exp(-torch.square(dist_c1_to_c2) / (0.2 ** 2))
   
   move_condition = is_c1_grasped & ~is_aligned
   total_reward = torch.where(move_condition, r_lift + r_move, total_reward)
   
   # ------------------------------------------------------------------
   # [Stage 4 & 5] Align, Stack & Release Mode: 목표 상단에 도달하여 안착 및 검증할 때
   # ------------------------------------------------------------------
   r_stack_bonus = 10.0  # 정렬 및 적재 성공 일시 보너스
   r_stability = torch.where(dist_c1_to_c2 < 0.05, torch.ones_like(total_reward) * 5.0, torch.zeros_like(total_reward))
   
   stack_condition = is_c1_grasped & is_aligned
   total_reward = torch.where(stack_condition, r_stack_bonus + r_stability, total_reward)
   
   return total_reward

3. 고급 기능: 커스텀 이벤트 핸들러 연동 (_events.py)

# mdp/franka_stack_events.py 의 내부 구조 설계 팁
def check_grasp_success(env: ManagerBasedRLEnv) -> torch.Tensor:
   """그리퍼 양쪽 손가락 사이의 거리와 물체의 크기를 비교하여 파지 상태 판정"""
   robot = env.scene["robot"]
   
   # Franka 그리퍼 조인트 각도/위치값 추출 (예: panda_finger_joint1, joint2)
   finger_pos = robot.data.joint_pos[:, 7:9] 
   gripper_width = finger_pos[:, 0] + finger_pos[:, 1]
   
   # 그리퍼가 꽉 닫히지 않고 큐브 두께(예: 5cm -> 약 0.04m~0.06m 사이)를 유지하고 있다면
   # 물체가 손가락 사이에 끼어 파지된 것으로 판단하여 True(1) 반환
   grasped_mask = (gripper_width > 0.03) & (gripper_width < 0.07)
   
   return grasped_mask

5. Integration with Modern RL Libraries (SKRL & Gymnasium 연동)
________________


NVIDIA Isaac Lab 프레임워크가 제공하는 강력한 병렬 GPU 가속 시뮬레이션 환경을 표준 Gymnasium 인터페이스로 패키징하고, 이를 최신 GPU 가속 강화학습 라이브러리인 SKRL(Sequential Knowledge Reinforcement Learning)의 PPO 에이전트와 직결하여 고속 학습 파이프라인을 구축하는 실전 실행 가이드입니다.
Isaac Lab과 SKRL의 연동은 시뮬레이션 물리 데이터(관측, 보상 등)를 CPU로 복사하지 않고 GPU VRAM 위에서 직접 신경망 역전파(Backpropagation)로 전달하기 때문에 극도의 훈련 가속을 달성할 수 있습니다.
🔌 1. Gymnasium 표준 인터페이스 및 벡터화 래핑
Isaac Lab의 매니저 기반 환경(ManagerBasedRLEnv)은 기본적으로 gymnasium.Env 사양을 충족하도록 설계되어 있습니다. 병렬 대량 학습을 수행하기 위해 여러 환경을 묶는 벡터화 환경(Vectorized Environment) 구조가 어떻게 SKRL과 상호작용하는지 코드로 설계하는 단계입니다.
팩토리 기반 환경 생성 패턴 (scripts/skrl/train.py 내부 핵심 로직)
Isaac Lab 전용 Gymnasium 환경 생성 유틸리티를 사용하여 GPU 상에 병렬로 텐서 환경을 구축합니다.
Python
import gymnasium as gym
import torch

# Isaac Lab 전용 런타임 환경 래퍼 임포트
from omni.isaac.lab_tasks.utils.wrappers.skrl import SkrlVecEnvWrapper
from omni.isaac.lab.envs import ManagerBasedRLEnvCfg

def create_isaaclab_gym_env(task_name: str, num_envs: int, headless: bool):
   """Isaac Lab 환경을 생성하고 SKRL 텐서 포맷에 맞게 래핑하는 함수"""
   
   # 1. Gymnasium 레지스트리에서 사전 등록된 프란카 태스크 로드
   # 예: "Template-Lift-v0"
   env = gym.make(
       id=task_name,
       num_envs=num_envs,    # 병렬 구동할 환경 개수 (예: 16, 32, 64)
       headless=headless,    # GUI 화면 오프셋 여부
   )
   
   # 2. SKRL 전용 벡터화 환경 래퍼 적용 (VRAM 간의 데이터 다이렉트 통신 보장)
   env = SkrlVecEnvWrapper(env)
   
   return env

⚙️ 2. SKRL PPO 알고리즘 하이퍼파라미터 구성 (skrl_ppo_cfg.yaml)
SKRL 라이브러리는 하이퍼파라미터를 YAML 설정 파일로 분리하여 관리하는 아키텍처를 선호합니다. 각 태스크 폴더 하위(agents/skrl_ppo_cfg.yaml)에 매핑되는 신경망 아키텍처 및 PPO(Proximal Policy Optimization) 최적화 제어 사양입니다.


YAML




# source/franka_isaaclab/franka_isaaclab/tasks/manager_based/lift/agents/skrl_ppo_cfg.yaml

seed: 42

# 1. 신경망 아키텍처 정의 (Multi-Layer Perceptron)
models:
 policy: # 행위 신경망 (Actor)
   class: GaussianMixin
   clip_actions: True
   net: [256, 256, 128] # 은닉층 구조
 value: # 가치 평가 신경망 (Critic)
   class: DeterministicMixin
   net: [256, 256, 128]

# 2. PPO 알고리즘 하이퍼파라미터 세팅
agent:
 class: PPO
 rollout_steps: 24       # 수집할 타임스텝 수 (배치 생성용)
 mini_batches: 4         # 미니배치 분할 개수
 epochs: 5               # 에포크 반복 횟수
 learning_rate: 3.0e-4   # 학습률 (Adam Optimizer)
 discount_factor: 0.99   # 할인 요인 ($\gamma$)
 lambda_gae: 0.95        # Generalized Advantage Estimation ($\lambda$)
 clip_policy_ratio: 0.2  # PPO 클리핑 경계값 ($\epsilon$)
 entropy_loss_scale: 0.001 # 탐색 강화를 위한 엔트로피 가중치
 value_loss_scale: 1.0
 kl_threshold: 0.015     # KL Divergence 상한선 규칙

# 3. 트레이너 실행 스케줄
trainer:
 class: SequentialTrainer
 timesteps: 36000        # 총 학습 타임스텝 수
 close_environment_at_exit: True

🧠 3. SKRL 에이전트 구축 및 파이프라인 연동
래핑된 Gymnasium 환경 객체와 YAML 파라미터를 소스코드 단에서 조립하여 실제 학습 루프를 트리거하는 핵심 연동 프로세스입니다.


Python




import os
import yaml
from skrl.agents.torch.ppo import PPO, PPO_DEFAULT_CONFIG
from skrl.trainers.torch import SequentialTrainer
from skrl.utils import set_seed

def train_skrl_pipeline(env, cfg_path: str, log_dir: str):
   # 1. 시드 고정 및 설정 파일 로드
   set_seed(42)
   with open(cfg_path, "r") as f:
       cfg = yaml.safe_load(f)
       
   # 2. SKRL 표준 에이전트 환경 정보 주입
   # 환경의 관측 공간(Observation Space)과 행동 공간(Action Space) 규격을 자동 매핑
   agent_config = PPO_DEFAULT_CONFIG.copy()
   for k, v in cfg["agent"].items():
       if k != "class":
           agent_config[k] = v
           
   # 3. 관측/행동 규격을 바탕으로 에이전트 인스턴스 초기화
   agent = PPO(
       models=None, # 내장된 기본 MLP 네트워크 모델 자동 생성 레이어 활용 가능
       memory=None,
       cfg=agent_config,
       observation_space=env.observation_space,
       action_space=env.action_space,
       device=env.device
   )
   
   # 4. 순차 트레이너(Sequential Trainer) 배포 및 시작
   trainer_config = cfg["trainer"]
   trainer = SequentialTrainer(
       env=env,
       agents=agent,
       cfg=trainer_config,
       output_dir=log_dir # 텐서보드 로그 및 최고 가중치 저장이 이루어질 경로
   )
   
   # 학습 실행 시작 (GPU 하이퍼 드라이브)
   trainer.train()

6. GPU-Accelerated Simulation (VRAM 기반 고속 학습)
NVIDIA Isaac Lab의 최대 장점인 GPU 가속 시뮬레이션(GPU-Accelerated Simulation)을 극대화하여, CPU-GPU 간의 데이터 병목 없이 VRAM(비디오 메모리) 안에서 모든 물리 연산과 강화학습 역전파를 초고속으로 처리하는 실전 실행 가이드입니다.
전통적인 강화학습(예: OpenAI Gym + 가제보/뮤조코 CPU 구동)과 달리, Isaac Lab은 수백~수천 개의 가상 세계를 고전적인 그래픽 카드 파이프라인(PhysX On GPU) 위에 통째로 올려 학습 속도를 수십 배 이상 가속합니다. 이를 실제로 제어하고 최적화하는 방법을 구체적으로 정리해 드립니다.
🧠 1. GPU 가속 파이프라인의 핵심 원리 (End-to-End GPU)
일반적인 환경에서는 시뮬레이터(CPU)가 물체의 위치를 계산한 뒤 이를 파이썬을 거쳐 GPU(AI 신경망)로 전송합니다. 이 과정에서 엄청난 데이터 전송 병목(PCIe 호스트 역전파 병목)이 발생합니다.
Isaac Lab의 아키텍처는 이를 아래와 같이 혁신합니다.
   * PhysX GPU 파이프라인: 시뮬레이션 공간의 충돌, 중력, 관성 연산이 GPU 코어에서 직접 계산됩니다.
   * 리얼타임 텐서 API: 계산된 로봇의 관절 위치, 물체 좌표가 CPU 메모리로 내려가지 않고 PyTorch 텐서(torch.Tensor(device="cuda")) 형태로 VRAM에 즉시 박힙니다.
   * SKRL 다이렉트 통신: SKRL의 PPO 에이전트는 VRAM에 대기 중인 이 텐서를 그대로 가져가 신경망 가중치를 업데이트하므로, 데이터 복사 속도가 $0$에 수렴합니다.
⚙️ 2. GPU 가속을 극대화하는 3대 핵심 파라미터 제어법
실제 스크립트를 실행할 때 VRAM 가속 효율을 결정짓는 핵심 인자들의 설정 방안입니다.
① 헤드리스 모드 (--headless)
모니터에 3D 그래픽 화면을 그리는 렌더링(Rendering) 연산은 GPU 자원(VRAM 및 셰이더 코어)을 엄청나게 잡아먹는 주범입니다. 본격적인 학습을 진행할 때는 GUI 창을 완전히 끄는 --headless 인자를 주어 GPU가 오직 '물리 연산'과 '신경망 학습'에만 100% 집중하도록 만듭니다.
   5. 효과: 학습 속도가 약 3배~5배 이상 빨라지며, VRAM 소모량이 수 GB 이상 절약됩니다.
② 환경 병렬화 튜닝 (--num_envs)
GPU는 대규모 병렬 연산(Massively Parallel)에 특화되어 있습니다. 환경 개수가 너무 적으면(예: 1~4개) GPU의 수천 개 쿠다 코어들이 놀게 되어 효율이 극도로 떨어집니다. 그래픽 카드 사양에 맞춰 이 값을 대폭 끌어올려야 합니다.
   * VRAM 용량별 추천 설정 기준 (--num_envs 가이드):
   * RTX 3060 / 4060 (VRAM 8GB~12GB): 16 ~ 32 개 권장
   * RTX 3080 / 4070 / 5070 (VRAM 12GB~16GB): 32 ~ 64 개 권장
   * RTX 3090 / 4090 / 5080 (VRAM 24GB+): 128 ~ 512 개 이상 확장 가능
③ 시뮬레이션 디바이스 명시 (--device)
기본적으로 Isaac Lab은 시스템의 첫 번째 GPU(cuda:0)를 잡고 구동되지만, 멀티 GPU 환경이거나 명시적인 가속 배포가 필요할 경우 내부 설정을 파악해 두어야 합니다.

🛠️ 4. VRAM 오버플로우 및 크래시 트러블슈팅 가이드
GPU 가속을 세게 걸다 보면 물리적 하드웨어 한계로 인해 시뮬레이터가 튕기는 현상이 발생할 수 있습니다. 이때의 대처 요령입니다.
❓ 증상 1: Out of memory (OOM) 또는 Segmentation fault (core dumped) 발생
   * 원인: 병렬 환경 개수(--num_envs)를 너무 크게 잡아서 그래픽 카드의 물리 VRAM 용량을 초과한 경우입니다.
   * 해결책: --num_envs 값을 절반으로 줄여서 다시 실행하세요. (예: 64 ➔ 32)
❓ 증상 2: 헤드리스 모드가 아닌 GUI 모드(--headless를 뺌)에서 창이 뜨자마자 벌칸(Vulkan) 에러와 함께 다운됨
   * 원인: Isaac Sim 디스플레이 렌더러와 우분투의 모니터 주사율, 혹은 다른 백그라운드 프로세스(예: 웹 브라우저 탭, 블렌더 등)가 VRAM을 먼저 선점하고 있어 그래픽 메모리 충돌이 일어난 경우입니다.
   * 해결책:
   * VRAM을 잡아먹는 크롬 브라우저나 타 프로그램을 완전히 종료합니다.
   * 화면을 꼭 봐야 하는 디버깅 상황이라면 환경 개수를 대폭 낮춥니다. (--num_envs=2 또는 4)
   * 훈련 시에는 무조건 --headless 인자를 생활화합니다.
❓ 증상 3: GPU 사용률(GPU-Util)이 10% 미만으로 툭툭 끊기며 터미널 로그가 매우 느리게 올라감
   * 원인: 커스텀 보상 함수(rewards.py)나 관측 함수(observations.py) 내부에 PyTorch 텐서 연산 대신 파이썬의 for 루프문이나 CPU 기반 넘파이(numpy) 배열 변환 코드가 스며들어 병목을 일으키고 있을 가능성이 99%입니다.
   * 해결책: 코드 내부에서 .cpu().numpy() 또는 tolist() 같은 CPU 강제 변환 함수가 쓰였는지 전수 전조사하고, 모든 배열 제어 수식을 순수 GPU 기반의 주요 PyTorch 텐서 연산(torch.where, torch.norm 등)으로 전격 교체해야 가속 드라이브가 다시 살아납니다.

7. Checkpoint Management & Versioning (체크포인트 및 모델 관리)
________________


NVIDIA Isaac Lab 프레임워크와 SKRL 라이브러리 환경에서 훈련된 강화학습 모델을 안전하게 저장하고, 효율적으로 버전을 관리하며, 필요 시 언제든 학습을 재개하거나 추론(Inference)에 배포할 수 있도록 돕는 실전 체크포인트 관리 및 버전 관리(Checkpoint Management & Versioning) 실행 가이드입니다.
강화학습은 물리적 특성이나 하이퍼파라미터의 미세한 변화에 따라 성능 롤러코스터를 타기 때문에, 최적의 타이밍에 생성된 가중치를 보존하고 실험 히스토리를 트래킹하는 이 단계가 프로젝트의 최종 생산성을 결정짓는 방어벽이 됩니다.
📁 1. Isaac Lab + SKRL 체크포인트 저장 구조 이해
SKRL 라이브러리는 훈련 도중 모델의 단순 가중치(state_dict)뿐만 아니라 최적화 도구(Optimizer)의 가변 상태, 학습률 스케줄러의 진행도, 에포크 카운트 등을 하나의 파일(.pt)로 직렬화(Serialization)하여 패키징합니다.
본 프로젝트의 학습 스크립트를 실행하면 logs/ 디렉터리 하위에 아래와 같이 타임스탬프와 결합된 구조적 디렉터리가 자동 생성됩니다.


logs/
└── skrl/
   ├── franka_lift/                          # 태스크별 독립 공간
   │   └── 2025-12-07_19-34-59_ppo_torch/    # [버전 관리 핵심] 타임스탬프 기반 고유 실험 폴더
   │       ├── checkpoints/
   │       │   ├── agent_10000.pt            # 설정 주기마다 생성되는 마일스톤 백업
   │       │   ├── agent_20000.pt
   │       │   └── best_agent.pt             # 최고 보상(Highest Reward) 기록 시 자동 갱신되는 파일
   │       └── tensorboard/                  # 해당 실험의 성과 곡선 데이터 파일

⚙️ 2. 체크포인트 관리 파라미터 제어 기법 (train.py)
체크포인트를 얼마나 자주 저장할지, 어떤 이름으로 버전을 분리할지는 scripts/skrl/train.py 내의 SKRL 트레이너(Trainer) 인자 값을 통해 제어할 수 있습니다.
핵심 제어 코드 아키텍처 예시
Python
from skrl.trainers.torch import SequentialTrainer

# 트레이너 설정 딕셔너리 확장
trainer_cfg = {
   "timesteps": 36000,                  # 총 학습 스텝 수
   "save_interval": 5000,               # 5,000 타임스텝마다 중간 마일스톤 모델 백업 생성

}

trainer = SequentialTrainer(
   env=env,
   agents=agent,
   cfg=trainer_cfg,
   output_dir="logs/skrl/franka_lift/run_v1" # 저장 디렉터리를 커스텀 명명하여 버전 관리 가능
)

🚀 3. 실전 체크포인트 활용 시나리오 (실행 매뉴얼)
시나리오 A: 저장된 최고 성능 모델을 시뮬레이터에 올려 시각적으로 평가하기 (Play Mode)
학습이 끝난 후, 에이전트가 완벽하게 태스크를 수행하는지 검증하기 위해 최상위 가중치 파일인 best_agent.pt를 명시하여 로드합니다.


Bash




conda activate isaaclab
cd ~/franka_isaaclab

# 플레이 전용 가상환경 이름과 특정 날짜 폴더의 베스트 에이전트 가중치 파일 경로를 지정하여 실행
python scripts/skrl/play.py --task=Template-Lift-Play-v0 --checkpoint=logs/skrl/franka_lift/2025-12-07_19-34-59_ppo_torch/checkpoints/best_agent.pt

시나리오 B: 시스템 다운이나 팅김 현상으로 멈춘 학습을 마지막 상태부터 이어 학습하기 (Resume Mode)
훈련량이 부족하여 타임스텝을 늘려 추가 학습을 진행해야 하거나, 중간에 전원/세션이 끊겼을 때 처음부터 다시 학습하지 않고 마지막 마일스톤 파일부터 뇌를 이어붙여 학습시키는 필수 기법입니다.


Bash




# --resume 인자와 함께 이어갈 직전의 체크포인트 파일 경로를 주입하여 훈련 스크립트 실행
python scripts/skrl/train.py --task=Template-Lift-v0 --resume --checkpoint=logs/skrl/franka_lift/2025-12-07_19-34-59_ppo_torch/checkpoints/agent_20000.pt --headless

💡 Resume 모드의 장점: SKRL은 해당 가중치 파일 내부에 저장되어 있던 Optimizer의 모멘텀 값과 learning_rate 상태를 그대로 복원하므로, 급격한 성능 하락(Policy Shock) 없이 자연스러운 연속성 훈련이 이루어집니다.
📊 4. 체계적인 모델 버전 관리(Versioning) 모범 사례
실험 횟수가 10회, 20회 이상 넘어가면 어떤 파일이 어떤 하이퍼파라미터로 구동되었는지 잊어버리는 병목이 생깁니다. 이를 방지하기 위한 실전 팁입니다.
1단계: 실험 가시성을 높이는 '폴더 식별 명명법' 적용
훈련 스크립트를 구동할 때 하이드라(Hydra) 아웃풋 매니저나 파이썬 실행 인자를 튜닝하여, 날짜 뒤에 내 핵심 변경 사항을 태깅하도록 훈련 모듈을 실행합니다. (예: 2025-12-07_19-34-59_lr_3e-4_batch_64)
2단계: TensorBoard와 Checkpoint 파일의 1:1 매칭 검증
텐서보드를 열어 여러 실험 곡선을 띄워놓고 최적의 교차점을 찾습니다.
Bash
tensorboard --logdir=logs/skrl/

   * 분석 요령: 브라우저 창에서 run_A 곡선이 25,000 스텝에서 가장 높은 Reward 피크를 찍고 그 이후 과적합(Overfitting)으로 하락했다면, 해당 날짜 폴더의 checkpoints/ 내부에서 25,000 스텝 근처에 생성된 agent_25000.pt 파일을 수동으로 복사하여 별도의 production_model.pt로 아카이빙 관리합니다.
3단계: 가중치 자산 메타데이터 기록 자동화 예시
새로운 실험 버전을 릴리즈할 때마다 아래와 같은 템플릿 형태로 텍스트 파일(experiment_note.txt)을 생성하여 해당 타임스탬프 폴더 안에 넣어두는 습관을 들이면 대규모 Sim2Real 프로젝트에서 혼선을 완벽하게 예방할 수 있습니다.
